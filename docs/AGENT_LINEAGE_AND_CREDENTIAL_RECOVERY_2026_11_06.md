## 工程记忆来源

- Agent 和自动生成的项目记忆由宿主读取同一 Agent、同一工作区的任务及其首条持久用户消息，核对原始任务输入，记录来源任务、会话、消息和精确内容指纹；证据中不复制来源正文。调用方不能提供宿主保留的证据字段。
- 读取时检查来源仍在、仍属于原范围，来源正文和记忆正文的修订仍一致。已绑定而失效的条目保留在管理列表供复核，不进入 Agent 检索或记忆列表工具。旧无证据记录保留并标明未核验；手动记录不冒充有消息证据。来源一致只证明版本对应，不证明记忆内容的事实正确性。
- 上下文诊断保留当时选中的记忆 ID、修订及来源状态。恢复不重用旧检查点中的记忆正文；后续模型请求前重新核对引用。历史列表工具正文的模型输入副本失效时改为可重新读取的占位提示，保留调用与结果配对以及原有脱敏回执。确定性压缩不把记忆列表正文转入无来源标识的历史摘录。
- 工作区记忆条目复用原信息行显示来源状态；只在来源匹配时展示消息编号。项目与个人范围保持隔离，不改写已有用户/助手回复或历史模型自由文本摘要。

入口：`siyi/app/memory/lineage.py`、`memory/service.py`、`context/assembler.py`、`context/budget.py`、`runtime/runner.py` 和 `desktop/frontend/src/components/memory/MemoryManager.tsx`。复用现有 SQLite 元数据，不加表或迁移现用数据库。

## 模型配置与密钥保存

新 Key 保存到由规范化 Provider 目标和随机代数派生的独立候选别名。配置文件的原子替换是唯一启用点：配置只含不透明代数与版本，不含密钥值。后台锁内比较期望配置版本、检查任务状态；前端同时核对当前 Sidecar 端点代际。旧格式可读；进入新保存协议后，过期或无版本的写入不能覆盖新设置。

| 情况 | 结果 |
| --- | --- |
| 候选 Key 写入失败或未获确认 | 不提交配置，原槽位不覆盖、不删除。 |
| 版本冲突、活动/排队/可恢复任务阻止轮转、配置原子替换失败 | 不启用此次候选；未提交的候选不替代原配置。 |
| 配置可能已提交，但响应中断 | 只读核对当前配置是否指向本次唯一候选。不能确定就提示待核，不重放 PUT，不删除旧或候选槽位。 |
| 已提交槽位缺失 | 拒绝凭据路径，不回落原别名或环境密钥；本机模型与显式本机诊断不读取云密钥。 |
| 同目标只改模型等设置、Key 留空 | 保持已选代数，不读写原 Key。 |

本轮不自动清理候选或历史槽位；这不是跨 Windows 凭据库和文件系统的通用事务，也不是原生凭据库实机验收。同一地址轮换 Key 同样受任务保护，有可恢复任务时明确拒绝，不擅自终止任务。客户端需要使用配套 Sidecar，不能把只升级前端视为完成。

入口：`desktop/frontend/src/shared/modelSettings.ts`、`modelCredentials.ts`、`api.ts`，`siyi/app/api/routes/system.py`、`providers/configuration.py`、`configuration_guard.py`。`contracts/model_credential_alias_v1.json` 由 TS 和 Python 共同验证 6 个固定向量，包括旧别名、代数隔离、中文地址、默认端口与路径大小写。
