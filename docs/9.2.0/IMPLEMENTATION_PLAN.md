# 司忆 v9.2.0 实施计划

## 目标

在不破坏现有模型工具名称和暂停任务快照的前提下，建立 Provider 无关的核心文件操作契约。逻辑操作使用 `file.*` / `directory.*` 名称，模型传输层继续兼容现有下划线工具名。

## 现状审计

- `safe_path()` 已完成路径标准化、目录穿越、UNC、设备路径、盘符相对路径、软链接与 Junction 越界防护。
- 现有读写已支持 UTF-8/UTF-16/GB18030、换行保留、二进制识别、2 MB 读取限制和 5 MB 写入限制。
- 写入使用临时文件 + `os.replace`；覆盖、复制、移动、创建和删除均先保存 `.agent-backups` 事务清单。
- 已有变更列表、单变更恢复、任务级逆序回滚、版本冲突检测和结构化结果。
- 缺口是统一点号操作 ID、同一调用的 dry-run、目录安全删除、批量事务上限和更完整的 I/O 错误字段。

## 实施

1. 新增文件能力引擎，将 15 个逻辑操作映射到现有稳定工具实现。
2. 所有变更操作支持 `dry_run`，只返回规范化路径、风险、影响范围和预览，不写磁盘。
3. 增加可恢复目录删除；拒绝工作区根、备份目录、超出批量上限或包含过多条目的目录。
4. 增加最多 50 项的批量执行；任一项失败时按任务/批次逆序恢复本批次已经完成的变更。
5. 结构化记录 source、destination、change_id、版本、错误类型、系统错误号和可重试性。
6. 保留现有工具协议作为兼容适配器，避免 Provider 工具名称和已持久化任务发生漂移。

## 验收

- 创建、读取、patch、重命名、移动、删除和恢复闭环；
- 同名冲突、被占用、无权限、超大文件、非 UTF-8、路径不存在；
- 工作区外访问、目录穿越与内部备份目录访问拒绝；
- dry-run 零写入；
- 批量中途失败自动回滚；
- 目录删除可恢复；
- Agent 停止后仍可通过持久事务清单恢复；
- 专项、完整后端、前端、Rust、Eval、隐私、性能和桌面封包门禁通过后才更新 v9.2.0。

## 不做

- 不删除或迁移用户工作区内容；
- 不扫描工作区外文件；
- 不推送 GitHub；
- 不调用付费模型；
- 不执行 24 小时耐久测试。
