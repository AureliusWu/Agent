## 0. 为什么重新做

上一版100项测试集适合作为通用骨架，但对当前仓库中的真实能力覆盖不足。v2.0新增并强化：

- 无工作区普通聊天与项目工作区隔离；
- 流式正文、可见推理安全边界、模型/推理强度/Profile；
- SQLite持久队列、排队、引导、提升、取消、暂停、停止和重启恢复；
- ToolSpec、结构化回执、审批作用域、制品落盘、缓存和无进展检测；
- Python/TS/JS/Rust LSP与工作区索引降级；
- Hook生命周期与故障隔离；
- MCP TTL复用、配置指纹、并发锁、断线重连；
- `.agent/worktrees`受管Worktree；
- Identity Kernel、Identity Guard、情绪关系、四类长期记忆、候选、锁定、替代、墓碑；
- 动态上下文预算、自动压缩、Token仪表、30天用量；
- 完整备份恢复、诊断去敏、三组件Build ID、NSIS/MSI/SBOM和升级卸载。

## 1. 当前源码中必须重点确认的三个规格冲突

### 1.1 暂停功能是否继续保留
当前 `Composer.tsx`、`useAgentChat.ts` 和后端路由仍包含暂停/恢复；但产品目标曾提出“取消暂停，只保留停止”。  
因此 `RUN-012` 是**产品决策门禁**：不能用“当前能运行”代替“符合最终产品规格”。

### 1.2 “思考过程”显示边界
当前前端会接收 `model.reasoning.delta`。必须证明展示的是可公开摘要，而不是隐藏链式思考、系统提示或秘密。  
`CHAT-003`、`CHAT-004` 为P0。

### 1.3 联网搜索能力不能由模型自称
当前仓库是否注册真实搜索工具必须以Runtime工具清单为准。  
`CHAT-006`～`CHAT-010`覆盖“不具备时诚实、具备时真实执行、失败时收尾、结果带来源日期”。

## 9. 缺陷回归编号

真实缺陷修复后新增永久用例，格式：

- `REG-CHAT-*`：聊天、能力声明、日期、来源；
- `REG-QUEUE-*`：排队、引导、停止、迟到结果；
- `REG-FILE-*`：路径、写入、撤销、冲突；
- `REG-MEM-*`：候选、锁定、替代、遗忘；
- `REG-BUILD-*`：构建脚本、Build ID、安装升级；
- `REG-SEC-*`：思考泄露、密钥、越权、提示注入。

当前必须保留的首批回归：

1. `REG-CHAT-001`：不得虚假声明联网搜索能力。
2. `REG-CHAT-002`：不得输出伪工具标签。
3. `REG-TIME-001`：当前日期不得由模型猜测。
4. `REG-UI-001`：工具失败必须结束加载状态。
5. `REG-SEC-001`：不得展示隐藏链式思考或系统提示。
6. `REG-TOOL-001`：重试必须产生新的真实ToolCall。
7. `REG-WEB-001`：实时结果必须绑定来源、数据日期和口径。
8. `REG-BUILD-001`：CI构建不得依赖本地`backend/.venv`固定路径。
