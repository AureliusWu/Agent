# v16 费用未知语义与美元预算保护

本文件说明费用安全合同，不代表发行或真实模型资格已验收。

## 原因与修复边界

一次隔离的最小 DeepSeek 验证发现：模型未配置单价时旧实现返回 0，SQLite 兼容列保存 0，用量面板也显示零费用；正美元预算因此可能永远不耗尽。该请求本身由外部保守估值、16 输出 Token、零重试和一次调用限制单独约束，不能把它当作 Agent 全流程预算验收。

修复遵循数据可靠性原则：未知不是零，不根据金额正负猜测是否已知，不自动写入官方单价，不修改用户默认模型或配置。

## 费用数据合同

| 字段 | 含义 |
|---|---|
| `cost_status` | `known`、`unknown` 或 `partial` |
| `estimated_cost_usd` | 完整已知时为数字；有未知或未结算请求时为 `null` |
| `known_cost_usd` | 仅已确认部分的估值，不是完整账单 |
| `unknown_cost_requests` | 含未确认费用的请求记录数量 |
| `pending_cost_requests` | 仍有费用预留、尚未完成结算的请求数量 |

明确零费率且完整用量可以是已知零费用。没有请求记录时累计为已知 0。历史空 snapshot、有价格却缺少完整用量、损坏 snapshot 或未知重试费用不能按 0 填补；后来配置价格不能抹去历史不确定性。

schema 继续保持 46。已有非空数值列保留兼容存储；费用是否已知以每条 `model_runs.price_snapshot_json` 的冻结证据为准，公共 DTO 不把存储零当作可信费用。任务预留复用 `agent_tasks.price_snapshot_json`；历史数据库缺少该字段时，正美元预算调用安全拒绝，不静默改动用户数据库。

## 正美元预算调用

- 统一在 Provider transport 边界检查，Planner、Executor、压缩、子 Agent、Verifier 和返工共享根任务 ID。
- 单价必须显式包含 input/output，拒绝缺键、负数、布尔值、NaN 和 Infinity；绑定实际 Provider、规范化端点身份及模型。
- 历史按模型名配置的费率只属于原 `AGENT_MODEL_BASE_URL` 端点，不能自动继承给同名模型的其他网关。跨端点使用显式 scoped 定价键 `provider:endpoint_hash:model`，其中 endpoint_hash 按生产 `provider_identity` 生成，不能手写猜测。
- 在当前根任务租约下，通过 SQLite `BEGIN IMMEDIATE` 原子检查已知费用、所有在途预留与新请求估值；并发子请求不能各自穿过同一余额。
- 正预算请求只在本次调用中禁用隐含重试，不修改用户默认重试配置。无美元预算的多次重试，如果只返回最后一次用量，总费用仍不得称为完整已知。
- 写入 model_run 与移除预留在同一事务完成。取消、丢失租约、崩溃或未确认费用不能靠 TTL 自动释放并重放。
- 取消或结算时数据库不可写，错误仍作为费用安全异常传播，不能被终态或性能日志写失败替换。数据库可能无法保存终态；在当前进程内按数据库身份、根任务和租约 generation 共享熔断，阻止同代兄弟任务继续调用或使用已返回的结果。
- 熔断没有 TTL 自动清除；最多记录4096个身份，容量耗尽时仅正美元预算调用保守阻断。重启不能抹去数据库中未结算的预留；新代仍须处理未确认费用，不能盲目继续。
- 费用不明或实际已知费用超预算时停止后续工具与模型调用；不能截断真实返回用量或费用来制造通过。
- 自动标题不得绕过美元预算成为额外付费调用；受限任务使用已有本地标题 fallback。
- 多模态输入如无法建立可证明的计费估值，正美元预算请求安全拒绝，不把文本估值当作图片费用上界。

## 限制与验收

输入 Token 估计不是精确 tokenizer，本合同是估计式支出保护，不是服务商实际账单的硬上界。用户配置价格也不是从账单查询得到的价格。独立 Token、时间、上下文、权限和文件安全门禁不因此降低。

流式文本可能在最后用量/费用确认前已显示；工具结果返回模型或执行Tool前的费用检查不等于撤回已显示文本。错误注入验证取消/数据库失败不等于真实OS进程崩溃验收。

用量汇总的 totals/models 为全历史，period_days 只限制 daily。models/daily 来自已持久化 model_run；在途预留在 total/task 中单独展示，不把不同统计范围描述为同一份完整账单。

前端用量与执行轨迹复用同一费用显示策略；未知显示“费用未知”，partial 显示已知子集与未确认次数，pending 显示尚未结算，真实已知零费用仍显示 `$0`。测试应执行生产组件，而不只匹配源代码文字。

必须验证缺价零 HTTP、历史未知、缺用量、真实零费用、并发预留、取消与崩溃、租约漂移、预算异常跨阶段传播、自动标题、端点定价隔离，以及 totals/models/daily/task/phase/model_run 的一致 DTO。实际执行结果由当前 `TEST_MATRIX.json` 与不可改写的原始日志/JUnit记录，旧 rc9 和旧全量结果不能继承为修复后源码证明。
