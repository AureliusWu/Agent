# v16.0.0 模型连接与设置修复

日期：2026-10-29。范围为现有 Windows 用户测试基线的缺陷修复；保持产品版本 `16.0.0`，不移动已有 `v16.0.0` 标签，不把历史或跳过的正式验收改成通过。

## 已确认的故障

构建使用的 Python 在创建 SSLContext 时需要解释器附带的一份公开证书策略文件。此前 PyInstaller 收集了 SSL 模块，却漏收该资源，冻结后端在发出 HTTPS 请求前即返回 `FileNotFoundError`。开发解释器和 Mock 网络测试可以通过，不能证明冻结程序的真实 TLS 初始化正常。

新的 SSL hook 仅在解释器实际引用该资源时收集它，并核对已审核的精确大小与 SHA256；标准 Python 无需该文件。没有关闭证书校验、主机名验证或网络策略，也没有普遍允许 PEM 文件进入交付材料。

两个构建入口现在必须执行冻结后端的 `--tls-self-check`。该入口在应用、配置、日志和数据库初始化前检查 SSL 及 HTTPX，且不联网、不读取凭据。缺资源会阻止后续交付。

## 使用“模型与 API”

从“应用 → 模型与 API”或侧边栏进入。主要操作保持在同一个表单：

1. 选择提供商。
2. 输入 API Key；留空表示保留当前目标已有的密钥，不是删除。
3. 获取模型目录、选择模型，或手动添加提供商给出的模型 ID。
4. 点击“保存”。保存不强制联网，也不会发送模型对话。

API 基础地址、超时、输出预算、重试、流式输出及工具调用保留在“高级设置”。DeepSeek 支持官方根地址或 `/v1`，不能填完整 `/chat/completions` 接口地址。

“获取可用模型”和“检查连接”使用当前表单草稿，只请求模型目录，不先保存草稿，不调用 Chat，也不自动重试或跟随重定向。目录可达不等于模型对话、工具能力或账户余额已经验收。

## 数据、密钥与错误边界

- 不变更数据库 Schema，不导入、删除或清空现有聊天、模型和配置数据。
- API Key 仍存储在 Windows 凭据管理器，不写入 JSON、日志、浏览器存储或 GitHub。
- 原官方 DeepSeek 的旧密钥保持兼容；新保存的密钥按提供商和地址作用域隔离，切换目标不能自动外发原目标密钥。
- 活跃或可恢复任务存在时，不允许更换凭据目标，以免持有旧授权的任务被改发至另一服务；模型选择仍遵守原运行时边界。
- 密钥缺失、凭据读取失败、401/403、限流、DNS、TLS、超时和打包缺文件分别提供可操作的错误说明，不再笼统归为“没有 API Key”。

## 验证范围

本轮使用 synthetic 凭据、Mock HTTP、隔离数据库和冻结后端的离线检查。`scripts/smoke-provider-connection.py` 仅允许固定的诊断接口，默认不连接外网。显式 `--probe-deepseek` 仅用故意无效的合成凭据请求官方 `/models`：预期 401 只证明 TLS 和远端接口可达，不证明真实账号鉴权或模型对话成功。

本轮不读取真实密钥做模型验证，不发送付费 Chat，不执行真实麦克风或 Qwen 验收，也不重新启动完整安装包／RC 发布链。当前二进制身份及已实际完成的验证见 `CURRENT_DELIVERY.json` 和本机交付回执；源码、冻结包与文档提交必须分别记录，不手改嵌入构建身份。
