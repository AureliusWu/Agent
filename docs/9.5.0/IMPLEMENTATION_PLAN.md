# 司忆 v9.5.0 实施计划：上下文、队列与任务恢复

## 基线与边界

- 基线为本地 v9.4.0 发布提交 `11dc06e293fceba201462c2d3cff89060e05f3a3`。
- 复用现有持久队列、租约、执行分段、检查点、结构化上下文和停止/恢复能力，不建立第二套运行时。
- 仅 Windows PC、本地修改和本地封包；不推送 GitHub，不调用 DeepSeek 付费接口。
- 用户已排除 24 小时耐久，标为 `NOT_APPLICABLE`。

## 缺口实施

1. 在每个工具调用完成后写入 checkpoint；副作用调用捕获最新工作区证据。
2. 模型上下文自动压缩前先保存 typed context、关键事实、任务目标、限制和完成结果。
3. 长任务在轮次、工具调用和安全停止点生成持久进度摘要与外显事件。
4. 提供统一任务状态快照，外显 Token、上下文、队列、检查点、完成/待办和恢复状态。
5. 新消息默认排到末端；运行中引导保持 `now/next/later` 排队与安全点消费，验证五条指令的稳定顺序。
6. 产品层移除暂停语义，只保留停止；历史 paused 数据仅在迁移时转为 interrupted 以兼容旧数据库。
7. 停止保留已完成步骤、工具回执、文件结果和最近 checkpoint；重启恢复不重放已完成副作用。
8. 延续可配置轮次、工具调用、重复调用、连续失败、无进展和 Token 上限，补齐无限循环验收。
9. typed context 继续严格区分 FACT、INFERENCE、CONSTRAINT、DECISION、OPEN_QUESTION、NEXT_ACTION 和 EVIDENCE_REF。

## 专项验收

- 无工作区连续 20 轮身份连续性。
- 临时工作区连续 20 轮文件任务，实际文件结果与 checkpoint 对应。
- 运行中追加 5 条引导，FIFO 顺序与优先级规则正确。
- 模拟进程中断、租约过期和运行时重启后可恢复，已完成副作用不重放。
- 上下文压缩后核心身份、目标、限制、事实类型和待办不丢失。
- 界面和 API 无暂停动作，仅提供停止与恢复。

## 发布门禁

专项、后端全量、真实 qwen3:4b、Core Eval、前端、Rust、隐私、封包、安装数据保留和性能全部通过后，才统一更新到 v9.5.0。
