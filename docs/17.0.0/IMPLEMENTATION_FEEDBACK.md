# 司忆 v17.0.0 验收记录

仅记录本次冻结源码的实际验收，不继承 v16.0.3 的门禁结论。

- `b225c70` 功能冻结版：后端全量 4,241 通过、29 跳过、1 失败，覆盖率 85.03%。失败仅为旧应用仍在运行导致启动器单实例保护触发，后续关闭窗口后原 5 项通过。首次实际替换发现便携启用脚本只允许 v16，原程序和启动校验清单自动还原，原数据库保持不变；保留原始失败记录。
- 最终制品 `70bca4e` / `d2be72ae3b19f82ea937dfe2` 只在前一提交之上调整 Windows 启用/启动脚本的版本支持、补充测试和计划记录，运行时功能源码未变。修正后的启动器 7/7、启用与静默入口 10/10、Rust 17/17、固定离线评估 40/40；前端测试与最终构建均通过。没有把前一轮后端报告改写成全绿，也没有在最终提交重跑整个后端。
- 冻结 API 接受了同 ID 同参数的重试并返回原回执、拒绝冲突参数；同文引导取消只移除确切的一条，独立 SQLite 读回与 API 一致。前端刷新/接续模拟和持久事件测试证明不展示旧尝试结果或确认项。记忆回归直接检查 Runner 发给 Provider 的合成请求，两个执行路径都没有自动提取个人记忆，工作区仅有自己的项目记忆。没有回溯修改历史。
- 最终便携包逐项校验 250 个文件。原生隔离窗口完成新建会话、Mock 回复、准确恢复待办和正常退出；独立 SQLite 验证只保存/恢复一次。实际替换通过旧数据归属检查，原启动入口打开 v17.0.0，桌面渲染和本机核心健康读回一致。对比已备份的升级前数据库，五张用户数据/模型记录表及配置保持一致，schema 46 且 `quick_check` 通过。旧程序、原启动器和数据库均在本机可回退，未修改用户密钥。
- 100 对同机 SQLite/Python 合成测量：活跃任务列表 p50 9.559→9.575 ms，详情 p50 15.474→12.686 ms；含 500 条消息和 200 条引导的历史过滤 p50 5.598→6.534 ms（+16.7%，绝对增量约 0.94 ms，性能警告），50 条已取消引导从模型历史中全部排除。不把这些读回数据解释为整机或模型性能。
