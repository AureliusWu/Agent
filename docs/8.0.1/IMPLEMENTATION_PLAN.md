# 司忆 v8.0.1 分阶段实施计划

## 基本规则

- 当前产品版本保持 `8.0.0`。
- 不推送远程仓库，除非管理员明确要求。
- PASS 必须绑定命令、UTC 时间、Build ID 和本地证据文件。
- 缺环境、未执行、静态审查和推断不得判定 PASS。
- 所有场景数据使用临时 AppData；真实用户数据禁止进入测试。

## 阶段 0：基线与证据基础设施

- 冻结 Git、工作树、Build ID 和 220 项矩阵基线。
- 建立 18 个真实场景目录契约。
- 建立 PASS 证据验证器。
- 建立临时 AppData 和桌面 Harness 接口。

完成条件：场景目录定义全部通过静态契约验证；伪 PASS 被验证器拒绝。

## 阶段 1：上下文与成本

- EFF-001 固定前缀字节稳定。
- 文件内容哈希和增量引用。
- 工具输出 Artifact 去重。
- FACT / INFERENCE / CONSTRAINT / DECISION / OPEN_QUESTION / NEXT_ACTION / EVIDENCE_REF 类型保持。
- Provider 用量与阶段费用账本。

完成条件：EFF-001~008 均有实际运行证据。

## 阶段 2：长期执行与交付

- 统一 INTAKE 至 FINALIZE 阶段协议。
- 计划项稳定 ID、失败指纹和下一修复动作。
- 完善配额、退出、休眠、停止前检查点。
- 最终报告从数据库和回执聚合。

完成条件：RUN 剩余项及 LONG-003、004、007、008 通过。

## 阶段 3：搜索、工具和真实对话

- 搜索证据协议与多来源冲突表示。
- 工具调用全生命周期。
- NEXT / STEER 消息隔离。
- Provider 失败后的有界切换与 UI 收尾。

完成条件：RS-004~009 通过。

## 阶段 4：工程理解

- TypeScript、Rust、Python LSP 能力闭环。
- 最小相关文件子图。
- Worktree 隔离与可审查 Diff。
- 三组真实多文件任务。

完成条件：三组任务均包含修改、失败修复和真实验证。

## 阶段 5：身份、记忆与人格

- 无工作区和模型切换连续性。
- 事实与推断来源保持。
- 候选确认、拒绝、替代、删除。
- 人格层关闭后的核心能力回归。

完成条件：RS-001、002、014 通过。

## 阶段 6：Evo 闭环

- 显式基线。
- 候选 A、反馈、候选 B。
- 最佳检查点、回退和 held-out。

完成条件：EVO-006、007、008、009、013 通过且预算未超限。

## 阶段 7：发布门禁

- 全量自动测试和桌面 E2E。
- 真实模型 Gate。
- 30 分钟、2 小时和 24 小时门禁，除非管理员对 v8.0.1 单独书面豁免。
- 故障注入、NSIS/MSI、隐私、依赖和性能。
- 证据聚合报告。
- 最后统一更新版本号为 `8.0.1`。
