# 司忆 v8.0.1 差距清单

基线：`docs/8.0.1/BASELINE.json`

## 结论

当前实现不是空白起点。Runtime 已具备持久任务、队列、检查点、恢复、操作幂等记录、结构化工具回执、Verifier、Token 汇总、缓存计数、身份与记忆治理等基础。v8.0.1 应在这些模块上收敛协议和补齐真实场景，禁止平行重写第二套 Runtime。

## 分领域差距

| 领域 | 已有基础 | 主要差距 | 首批动作 |
|---|---|---|---|
| 证据基础设施 | Eval 已有结构化结果和 Markdown 报告 | 真实场景没有统一目录、状态和 PASS 证据约束 | 建立 18 场景目录契约与验证器 |
| 桌面 E2E | NSIS 安装、升级、卸载烟测可运行 | 缺少稳定 UI 控制、截图、事件状态和故障注入 Harness | 单独建立 Windows Harness，使用临时 AppData |
| 长期执行 | 检查点、恢复、租约、操作去重已存在 | 阶段名未完全统一；休眠、配额、最终报告聚合未闭环 | 统一阶段协议并补真实恢复场景 |
| 上下文效率 | 分层组装、预算、缓存和压缩已有测试 | 固定前缀字节稳定性、文件增量注入、Provider 用量账本不足 | 先建立 EFF-001~008 可重复基线 |
| 搜索可信度 | Provider 和网络安全边界已存在 | 来源协议、冲突表示、UI 失败收尾缺真实闭环 | 建立 SearchEvidence 与 RS-004~006 |
| 工程理解 | Python LSP、workspace index、Worktree 已存在 | TypeScript/Rust LSP 和真实跨语言任务证据不足 | 补 LSP 能力探测和 3 组场景 |
| 身份记忆 | 后端身份核、候选确认、替代和删除已存在 | 模型切换、无工作区、人格关闭缺桌面证据 | 绑定 RS-001、RS-002、RS-014 |
| Evo | 官方固定 commit、Toy/CartPole 已真实运行 | 首次提交耗尽预算，缺反馈后二次候选 | 重做预算分段和候选检查点 |
| 发布 | v8 NSIS 生命周期、隐私、凭据、性能门禁已有证据 | MSI 管理员生命周期、桌面 E2E、真实长任务仍缺 | 所有缺口保持 BLOCKED/NOT_RUN |

## 关键风险

1. 当前工作树包含大规模未提交的 v8.0.0 目录收敛和功能改动；任何重置、覆盖或按 HEAD 比较都会损坏基线语义。
2. 方案要求 24 小时浸泡，但管理员此前对 v8.0.0 明确取消该测试；该豁免不会自动延续到 v8.0.1。若没有新的书面豁免，v8.0.1 的 LONG-005 必须执行或保持 NOT_RUN。
3. 真实模型 Key 只能由 Runtime 读取，测试证据不得记录 Key、请求头或完整敏感提示。
4. 桌面自动化必须操作隔离 AppData，禁止接触真实用户数据库和记忆。
5. 版本号只能在全部门禁完成后从 8.0.0 统一更新为 8.0.1。
