# RC 产物来源与传输修复

发布任务补齐 `actions: read`。选择的证据必须来自本仓库、当前发布提交、main 上手动执行且成功完成的正式 `rc-acceptance.yml`；latest run 与独立 attempt 元数据必须一致。

正式版本名称的 artifact 在完整分页中必须唯一，ID、仓库、源码、创建时间窗、大小和摘要都绑定到选择回执。下载按固定 ID 单次获取 ZIP，实际流式字节数和 SHA256 必须匹配后，才进入既有有界安全接收器；跨存储域重定向剥离凭据，Actions 与 Release 资产的域名边界分别保持受限。下载后再次核对 run、attempt 和 artifact 元数据，拒绝期间漂移。

原 importer、安装生命周期证据、不可变快照和总 RC gate 仍须独立通过。传输验证不会授予 RC 或发布资格，也不会把离线材料当成完整验收。

修复验证：233 项定向回归、4 项 scripted Eval 符合预期，真实模型调用为 0；工作流 PowerShell 语法和相关隐私检查通过。真实非正式小型 artifact 的 ZIP 大小、摘要与 API 元数据一致，原接收器仍正确拒绝其 RC 资格。

正式 RC 仍缺真实模型、同机性能、桌面、安装及人工材料。42 项原合同保持不变；应用版本不变，未创建新 tag 或发布资产。本次修复的 CI 不能替代这些门禁。
