# 司忆 5.0.0 实施计划

## 版本目标

5.0.0 聚焦“能力真实性与可验证交付”。运行时、界面和验收报告必须使用同一份真实能力状态；未配置、不可达或测试失败的外部能力不得展示为可用，也不得注入模型工具列表。

## 实施顺序

1. **能力真相源**：提供统一运行时能力接口，区分内置能力、工作区限定能力、MCP 已配置能力和当前不可用能力。
2. **MCP 联网闭环**：新增服务默认禁用；只有完成真实工具发现后才可启用。保存最近检查时间、状态、工具清单与去敏错误，并支持界面复测。
3. **界面可追溯**：扩展页显示可用、未测试、失败和停用状态；不再以“已填写 URL”等同于“具备联网能力”。
4. **全量验收编排**：180 项清单继续逐项判定；自动门禁只能作为对应证据，手动或 E2E 项没有独立场景证据时必须保持阻塞，不允许汇总测试冒充单项通过。
5. **发布收口**：执行后端、前端、Rust、核心、安全、多 Agent、专业 Agent、真实模型与 Windows 安装升级验收，再生成 5.0.0 制品。

## 暂不纳入

- 不内置依赖非正式网页协议的搜索抓取器。
- 不开放第三方任意代码、任意深度子 Agent 或自动放宽权限。
- 网页端、移动端、云同步、多人协作和最终视觉重构继续冻结。

## 完成标准

- 未通过发现测试的 MCP 不会被模型调用。
- 状态接口与扩展页能解释能力为何可用或不可用。
- MCP 失败不影响内置工具，错误信息不泄露凭据。
- 180 项报告对缺失证据诚实标记为 `blocked`。
- 正式桌面构建、升级、Sidecar 生命周期与构建指纹验证通过。
