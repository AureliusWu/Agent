# Agent v0.22.0 Release Engineering Report

## Scope

This milestone makes the existing Windows application reproducible, recoverable, diagnosable, and package-verifiable without expanding the Agent's runtime permissions or changing its primary interface.

## Delivered

- Added root `VERSION` as the release baseline and a structured metadata check across Python, npm, Cargo, Tauri, and lock manifests.
- Added committed Python `uv.lock` and exported `requirements.lock`; CI and desktop builds use Python/npm/Cargo locked installs.
- Added a Windows release workflow that verifies source, builds NSIS and MSI, uploads artifacts, and publishes tagged GitHub releases.
- Added a CycloneDX 1.5 SBOM generated from the Python, npm, and Cargo lock graphs.
- Fixed database transaction rollback and added automatic consistent backup before every schema upgrade, with restoration after migration failure.
- Added a credential-redacted diagnostic ZIP containing health, runtime boundaries, audit summaries, data-flow summaries, and bounded logs only.
- Fixed the packaged sidecar contract smoke from stale kernel 1.0 to current 1.2.
- Fixed desktop persistence so the database, logs, extensions, backups, and diagnostics use `%LOCALAPPDATA%\AureliusWu\Agent`.
- Added NSIS silent install/file verification/uninstall smoke and explicit NSIS/MSI Tauri targets.
- Added Windows installation, upgrade, recovery, diagnostics, and maintainer release documentation.

## Verification

- Release metadata: 7 sources consistent.
- Focused database, diagnostics, deployment, and API tests passed.
- Full backend suite: 231 passed, 1 skipped, 83.31% coverage.
- Representative scripted Runtime Eval: 4/4 passed with no false completion, permission violation, sandbox violation, or unrelated file modification.
- Frontend lint, production build, and credential-boundary scan passed; the bundle remains 361.54 kB (112.49 kB gzip), unchanged from v0.21.0.
- Windows desktop Rust tests: 3 passed.
- Python lock freshness, PowerShell syntax, workflow YAML parsing, and locked-component SBOM generation passed.
- Packaged sidecar reported version 0.22.0, schema 15, loopback-only deployment, kernel contract 1.2, and normal profile availability.
- Three packaged cold-start samples reached health in 1,526/1,555/1,617 ms (median 1,555 ms, worst 1,617 ms), below the 3-second critical-path budget.
- NSIS and MSI were produced; the current-version NSIS completed silent install, verified `Agent.exe` plus the bundled sidecar, and uninstalled cleanly.
- Remote CI and the Windows release workflow are recorded during release closeout.

## Boundaries

The diagnostic archive is designed for support evidence, not as a complete machine snapshot. Installer smoke verifies package installation and bundled executables but does not grant the installed Agent any broader filesystem access. Signed installers and automatic in-app updates remain separate distribution decisions.
