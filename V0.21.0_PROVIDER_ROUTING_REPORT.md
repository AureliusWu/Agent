# Agent v0.21.0 Provider Routing Report

## Scope

This milestone turns the existing OpenAI-compatible model client into an observable Provider Adapter with capability-aware, data-assisted routing and explicit user overrides.

## Delivered

- Extended the stable model Provider contract with `complete`, `capabilities`, and `probe`; raised the kernel contract to 1.2.
- Added persistent capability observations scoped by provider endpoint hash and model, without storing API keys or raw endpoints.
- Separated client protocol support from provider-observed streaming, native tool-call, vision, audio, and reasoning-parameter states.
- Used free model-list health checks and real successful calls as evidence; no automatic paid capability probe is performed.
- Added recent model success-rate, average latency, and average cost summaries with a minimum five-sample routing threshold.
- Added capability/reliability escalation while preserving existing task, failure, and repair routing.
- Fixed exact model overrides so they affect execution and survive resume.
- Added persistent automatic/low/medium/high reasoning selection in the chat composer.
- Added Provider capability and performance status to the extensions view.
- Added schema v15 persistence and indexes for capability lookup and recent model performance.

## Verification

- Focused Provider, capability, routing, database, kernel, task, and API tests: 72 passed.
- Representative scripted Runtime Eval: 4/4 tasks passed with no false completion, permission violation, sandbox violation, or unrelated file modification.
- Full backend suite: 229 passed, 1 skipped, 83.15% coverage.
- Frontend lint, production build, and security scan passed; the production bundle is 361.54 kB (112.49 kB gzip).
- Windows desktop Rust tests: 2 passed.
- A backup of the existing local SQLite database migrated to schema v15 with `quick_check` integrity, the Provider table, and both new indexes verified. The live database was not modified by this smoke test.

## Boundaries

Unknown capabilities remain unknown. A client implementation that can send a protocol field is not evidence that a configured provider supports it. Data routing does not act until enough recent samples exist, and explicit user overrides remain authoritative. Provider observation failures cannot fail a normal model response.
