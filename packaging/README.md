# Packaging

Installer and release-packaging definitions belong here. Build orchestration remains in `scripts/` and desktop shell sources remain in `desktop/`.

The frozen local-STT worker accepts only the desktop recorder's normalized 16 kHz mono 16-bit PCM WAV. Although `faster-whisper` declares PyAV as an upstream package dependency, both release build paths pass `--exclude-module av`, the artifact gate rejects any PyAV payload (including `av._core` and `av.libs`), and the product decodes the controlled WAV input with its built-in PCM decoder. PyAV/FFmpeg is therefore not shipped. It is the explicit `excluded_packages.av` exception in `python-license-policy.json`; do not move it into the notice-covered set unless arbitrary codec input is restored and the frozen artifact actually contains it.

The notice policy covers the complete Windows frozen-sidecar runtime closure, rooted at `aureliuswu-agent-backend` rather than only the top-level STT package. It follows selected extras such as `uvicorn[standard]` and includes the full `faster-whisper` closure: native or directly frozen packages such as NumPy, `hf-xet`, `filelock`, `fsspec`, `httptools`, `watchfiles` and `tqdm`, plus declared transitive packages such as FlatBuffers and Protobuf. `scripts/python_license_policy.py` recomputes that Windows/Python 3.12 closure from `siyi/uv.lock`; notice generation fails if a shipped runtime dependency or version is missing from the policy. Build-only tools remain in the SBOM as provenance but do not claim to be frozen sidecar payloads.

The CycloneDX SBOM remains the exact locked Python/npm/Cargo dependency and build-provenance inventory. Python components retain `agent:pythonScope`; notice-covered Python components carry `agent:thirdPartyNotice=covered`. PyAV remains visible for dependency provenance but has CycloneDX `scope=excluded` and `agent:frozenArtifactDisposition=explicitly-excluded`, so the SBOM does not imply that it is delivered. `THIRD_PARTY_NOTICES.txt` is generated from the validated notice policy, intentionally omits that non-shipped exception, and is published beside the installers and SBOM as a release asset. Never hand-edit either generated output.

The desktop sidecar is packaged with PyInstaller's `onedir` layout. Its executable remains the Tauri external sidecar, while the adjacent `_internal` runtime payload is explicitly bundled as a Tauri resource. Do not change this back to `onefile`: extracting the native STT dependencies on every application launch violates the cold-start budget. Both build scripts must synchronize and validate the complete `_internal` directory, and candidate builds must restore the pre-release runtime after verification.
