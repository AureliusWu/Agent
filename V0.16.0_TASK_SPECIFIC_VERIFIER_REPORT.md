# Agent v0.16.0 Task-Specific Verifier Report

## Scope

This release implements the V3 roadmap target for task-specific verification:

- `CodeVerifier`, `ApiVerifier`, `UiVerifier`, `DatabaseVerifier`, `SecurityVerifier`, and `DocumentVerifier`
- a reserved `MultimodalVerifier` contract that cannot claim completion yet
- stable `requirement_id` values from task planning through verification reports and the UI
- command classification that rejects successful but unrelated validation commands
- honest `partially_completed` results when required evidence is missing

The deterministic Planner now also limits each step to tools actually authorized for the selected professional Agent. This fixes file-organization plans that previously requested generic write tools outside the profile.

## Evidence Model

`backend/app/task_verifiers.py` owns domain detection, command relevance, and specialized evidence checks. `backend/app/verification.py` assembles persisted file, command, tool, and response evidence, then produces a `requirement_evidence` mapping. The frontend verification card displays:

```text
requirement_id -> verifier -> status -> evidence
```

Document verification respects expected final path state, so a correctly removed move source is not treated as a missing output.
